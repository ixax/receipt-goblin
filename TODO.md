# TODO

- **`services/webhook/src/` is a monolith worth splitting up.**
  `server.py` (webhook), `worker.py` (webhook-worker), `queue_client.py`, `clickhouse_ingest.py`, `loadtest.py`, `reparse.py` all currently live together, sharing one `requirements.txt`/`Dockerfile`, with `APP_ROLE` picking which role a given container plays at runtime (see "one image, `APP_ROLE` picks the role" in `AGENTS.md`).
  As of the `build_event()` relocation (webhook now only `XADD`s raw payloads onto `redis`; `webhook-worker` is the only thing that calls `build_event()`/touches ClickHouse for `/api/v1/metrics` traffic - see "Why a queue in front of ClickHouse" in `AGENTS.md`), the two roles' actual responsibilities are cleanly split even though the code/deploy artifact isn't.
  Splitting into separate modules/images was considered and deliberately not done yet - the current single image avoids duplicating a ~214MB image per role (6 roles: `webhook-1`/`webhook-2`/`webhook-worker`/`webhook-reparse`/`webhook-loadtest`/`clickhouse-migrate`) and `clickhouse_ingest.py` is used by both `server.py` (direct-to-ClickHouse `/api/v1/session-git-branch`/`/api/v1/plan-proposal` routes) and `worker.py`, so a clean split needs either a shared library or accepted duplication - revisit if/when the roles' dependencies or deploy cadence actually diverge enough to justify that cost.

- **`CwdChanged` hook doesn't fire (or fires with a broken payload) on `EnterWorktree`, so worktree sessions are invisible in the git-branch stats.**
  `hooks/report_git_branch.py` and the `/api/v1/session-git-branch` endpoint both work correctly - a manually piped payload (`echo '{"session_id":"manual-test-session","cwd":"<worktree path>"}' | python3 hooks/report_git_branch.py`) wrote a `session_git_branch` row with the worktree's branch within seconds.
  But triggering `EnterWorktree` for real in a live session did not produce a row - `session_git_branch` stayed on `git_branch='main'` until the manual call.
  All 17 sessions captured since the hook went live (~2026-07-25 19:20) show `git_branch='main'`, none show a worktree branch.
  Likely cause: `CwdChanged` either isn't emitted by `EnterWorktree`, or is emitted with a `cwd`/`session_id` that makes `hooks/report_git_branch.py`'s `git -C <cwd> ...` calls fail, silently hitting the `if not session_id or not git_branch: return` early-out (no POST, no stderr visible to us).
  Needs instrumenting the hook (e.g. temporarily log the raw stdin payload it receives) and repeating an `EnterWorktree` test to see what it actually gets.
  Until fixed, `git_repo` also stays collapsed to the main repo's origin-derived name across worktrees of the same repo (only `git_branch`/`issue_id` would differ) - worth deciding then whether to also capture an explicit worktree identity (e.g. toplevel path) rather than relying on branch name alone.
