Диагноз: исходный AGENTS.md — ориентировочно 5–6 тыс. токенов при бюджете ≤2 тыс. По тегированию из вашего же документа он распределяется примерно так: ~25% universal, ~50% deep-dive (обоснования архитектуры, «почему nginx именно так», истории инцидентов), ~20% task-specific (workflow'ы лоадтеста, детали панелей), ~5% дубли. Оптимизированная версия — ~1,6–1,9 тыс. токенов, всё вырезанное сохранено в двух deep-docs.

**Главные проблемы исходника**

1. Тройное дублирование: цепочка webhook→redis→worker описана во вступлении, в Repository layout (`queue_client.py`, `worker.py`) и в Architecture. Правило доступа к ClickHouse размазано по четырём буллетам (base rule + `clickhouse-analyst` + `sql-expert` + секция миграций). Правило «правило живёт ровно в одном файле» — теперь каждое сформулировано один раз.
2. Rationale вперемешку с правилами. «Никогда не рестартуй litellm без спроса» — universal, 1 строка. «Почему restart ≠ up -d и как мы это выяснили с Langfuse-ключами» — deep-dive, ушло в `agent_docs/incidents.md`.
3. Ирония: секция ASD-STE100 требует коротких предложений, а сам файл написан предложениями по 40–60 слов с вложенными скобками. Заодно там баг — оборванная фраза `Write "Turn the` и опечатка «standart».

**Что перенести не в файлы, а в hooks (техника 7 — ноль токенов, детерминизм).** Три «hard rules» — кандидаты на PreToolUse-hook с матчером Bash: блокировать `docker compose build|up` (подсказывать `make up`), блокировать `git checkout --|restore|reset --hard|clean` вне явного разрешения, блокировать `docker exec.*clickhouse-client`. После этого соответствующие строки из AGENTS.md можно сократить до одной каждая или убрать вовсе — машина гарантирует надёжнее промпта. Правило «stdlib logging, не print» частично закрывается ruff-правилом `T201`.

**Две оговорки**

- CLI-агностичность: я не выносил ничего в `.claude/rules/*.md` со скоупом по glob — Codex CLI их не читает, а ваш стек трекает оба CLI на равных. Паттерн «указатель в AGENTS.md → `agent_docs/*.md`» работает для обоих. Переносы в `.claude/agents/*.md` затрагивают только Claude Code-специфичную делегацию, что и так односторонне.
- Кэш (техника 11): AGENTS.md — часть кэшируемого префикса, поэтому такой рефактор делайте одним коммитом между сессиями, не по кусочку посреди активной работы. Секции «adoption status» (fastjson/LOG_LEVEL gaps) я перенёс в architecture.md ещё и поэтому — это самый изменчивый контент файла, каждое обновление ломало бы кэш проекта.

Финальный шаг по вашим же правилам: прогнать результат через `harness-expert` (он владеет AGENTS.md) и `stale-ref-sweeper` — перенос породил новые пути `agent_docs/*`, а часть формулировок исчезла из мест, куда могли ссылаться агенты и скиллы.
