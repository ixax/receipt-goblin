# Standardize skill storage on the Agent Skills open standard (`.agents/skills/`)

## Context

Skills currently live only under `.claude/skills/<name>/SKILL.md`.
There are 6 skills:

- `clickhouse-migration`
- `clickhouse-sql`
- `dashboard-panels`
- `harness-guardian`
- `md-format`
- `trace-debugging`

Claude Code reads that tree natively.
Codex CLI has no native access to it at all.
The only bridge is `agent_docs/harness-index.md`, a table generated by `scripts/sync_harness.py`.
Codex must read that table, then manually open each `SKILL.md` by path.
That generated index is the "костыль" the user wants to retire.

Research against current upstream docs (`code.claude.com/docs/en/skills`, `openai/codex` skills docs, agentskills.io) established two facts that shape the fix.

**Claude Code does not read `.agents/skills/` natively.**
A GitHub feature request for this (`anthropics/claude-code#66352`) was closed as "not planned."
Claude Code only scans `.claude/skills/`, `~/.claude/skills/`, and plugin skill dirs.
But it does follow symlinks: a `.claude/skills/<name>` entry may be a symlink to a directory anywhere else on disk, and Claude Code reads `SKILL.md` from the target transparently.

**Codex CLI's real convention is `.agents/skills/`, not `.codex/skills/`.**
The repo's own `harness-guardian` skill and `scripts/sync_harness.py` already assume a dual-harness symlink design.
But they encode the wrong target directory (`.codex/skills/`).
Codex has never read that path.
It reads `.agents/skills/` (repo root, and up the directory tree), per its own docs.

So the fix is not inventing a new mechanism.
It is correcting the target directory in a design this repo already half-built, and finishing it.
Make `.agents/skills/` the single real (non-symlinked) source of skill content.
Make `.claude/skills` a symlink into it.
Both harnesses then discover skills natively, with zero duplication and zero manually-maintained catalog for skills.

Confirmed with the user: the harness-index.md "Skills" table gets dropped entirely once this lands, since Codex no longer needs it.
The "Agents" table stays, since Codex has no subagent/Task-tool equivalent and still needs it.

## Approach

### 1. Move all skill content out, symlink the whole `.claude/skills/` directory

Move all 6 skill directories.
Then replace `.claude/skills/` itself with a single directory-level symlink to `.agents/skills/`.
Do not symlink one skill at a time.
A directory-level symlink means a future new skill dropped into `.agents/skills/<name>/` is picked up by Claude Code automatically, with no extra symlink step.

```
git mv .claude/skills/clickhouse-migration .agents/skills/clickhouse-migration
git mv .claude/skills/clickhouse-sql .agents/skills/clickhouse-sql
git mv .claude/skills/dashboard-panels .agents/skills/dashboard-panels
git mv .claude/skills/harness-guardian .agents/skills/harness-guardian
git mv .claude/skills/md-format .agents/skills/md-format
git mv .claude/skills/trace-debugging .agents/skills/trace-debugging
rmdir .claude/skills
ln -s ../.agents/skills .claude/skills
git add .claude/skills
```

`.agents/skills/<name>/SKILL.md` becomes the one real file.
`.claude/skills` becomes a single symlink (git tracks it as a normal symlink blob, mode 120000).
No content changes to the SKILL.md files themselves are needed for this step.
Frontmatter (`name`, `description`, `<version>` marker) stays as-is.
Going forward, a new skill is created directly under `.agents/skills/<name>/`.
Nothing is needed on the `.claude/` side.

Claude Code documents per-entry symlinks as supported.
Symlinking the entire `.claude/skills` directory, rather than one entry per skill, is not something the upstream docs explicitly call out.
Verify it works in this session before relying on it (see Verification step 4).
Fall back to per-skill symlinks if `.claude/skills` being itself a symlink turns out not to be honored.

### 2. Fix `harness-guardian/SKILL.md`'s dual-harness layout section

`.agents/skills/harness-guardian/SKILL.md` (after the move), "Dual-harness layout" section — replace:

> Skills follow the shared Agent Skills standard: one `skills/` directory in the repo, symlinked into
> `.claude/skills/` and `.codex/skills/`.

with the corrected, now-actually-implemented design.
`.agents/skills/` is the canonical directory: the real Agent Skills open-standard location Codex reads natively.
`.claude/skills` is a single symlink to it for Claude Code.

Route it through `harness-expert` during execution, not an inline edit.

### 3. Stop scanning skills in `scripts/sync_harness.py`; drop the Skills table

`scripts/sync_harness.py` currently builds two tables (Skills, Agents).
It scans `SKILLS_DIRS = [.claude/skills, .codex/skills]` (line 24) and `AGENTS_DIR` (line 25).
Per the user's decision, remove `find_skill_files()`, `SKILLS_DIRS`, and the `rows_skills`/"## Skills" section from `collect()` (lines 72-97, 109-111) entirely.
Keep only the Agents table.
Update `HEADER` (lines 28-35) to describe the file as agent-only now.
Update its docstring (lines 1-17) to explain skills are dropped because Codex discovers `.agents/skills/` natively.
The index remains solely because Codex has no subagent equivalent.

This is the concrete piece of "index hack" the user asked to remove.
